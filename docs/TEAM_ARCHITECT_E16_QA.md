# E16 — 課題から行動・育成へ

## 方針と実装

基準 main: bd916b432ea4dba9e2dbc0b0b3186439bec1708b。
ユーザーの最新要望に合わせ、従来の「すぐ指示書を生成」から、課題収集 → 優先順位 → 指示 → 結果・育成を追える入口へ変更した。デザインと全キャラクター画像は維持。

- 「課題・指示書」では一言の入力から「課題だけ保存」「指示書を作る」を選択できる。直接作成でも課題を保存し、指示書IDと一回だけ紐づける。
- 課題の現場メモ、目指す状態、優先度、保留、結果を編集・検索できる。作業完了は課題解決と同一視せず、結果の記録なしに結果確認済みにできない。
- 既存指示書は利用者の操作で課題一覧へ追加できる。指示書自体を移行・再生成・変更しない。
- 人材画面に正式な役職・直属上司と、コーチ／ホールマスターの兼務を追加。前﨑店長以外の実際の役職は未確認なので割り当てていない。
- コーチは社員またはCSキャスト、ホールマスターは社員。兼務だけでは上下関係や決裁権を付与しない。マネージャーの直属上司は店長。循環・未知の人物・不正な兼務を拒否する。
- 新しい初稿の未確認系統は仮案と明示し、開始前に設定を反映する。反映時は担当者から店長までの上司も編成に含め、発令者・報告先・MBTI伝達形式を更新する。担当・行動・期限・成果物は維持。実行中の系統を自動変更しない。
- 組織を設定してから作る新しい育成支援では、参加可能な選任コーチを候補とし、登録能力・担当件数で選ぶ。MBTIで能力や役職を推定しない。
- 課題に個人の育成目標、18能力の対象、支援者、観察結果、次回確認を任意で記録できる。作成する指示にも育成対象と確認行動を追記し、人材画面では本人の記録をまとめる。能力評価を自動変更しない。

## 保存と保護

schemaVersion 2 の任意フィールドとして issues / organization、および指示書の組織スナップショットを追加。旧JSONをそのまま読め、古い記録を暗黙に更新しない。同じ課題／指示書IDの追加復元を拒否し、既存能力・組織設定を優先する。
保存失敗時は入力と元の保存データを保持し、失敗した保存候補も全データ書出しに含めて復元できるようにした。破損した既存保存データの保護は継続する。
public/interview / supabase / 面接用データ・依存関係・公開設定には変更なし。AppDeployは使用しない。

- 面接回帰：JavaScript61件・Python3件成功。
- PC／スマホ幅の操作テスト：課題保存→育成記録→指示書へ接続→結果記録→本人の育成一覧→書出し・復元、正式組織の設定と反映、旧指示書の集約、容量不足時の復元、既存操作を確認。最終件数・CIと公開結果は下記へ追記する。

## 実用上の範囲

現時点ではこの端末内での集約。複数端末から共同で課題を投稿する機能・認証・クラウド同期は未実装。登録人材は既存7名。実際の役職・上司は利用者が一度設定する。MBTIは伝達の補助、能力は登録評価。生成AIは未接続で、具体化は既存ルールと入力内容による。
