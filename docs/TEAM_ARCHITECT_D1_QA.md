## 実用性の監査と変更

| 課題 | D1 の動作 |
|---|---|
| KPI は入力した目標の表示のみ | 値・観測日時（JST）・期間・出所・記録者を保存。達成方向を人が選択。観測日時順の最新値を比較 |
| 保留が「次の30分」に出る | 先行成果物完了済みの未着手・進行中だけ選出。全て保留の場合は判断の解消を案内 |
| 問題が自由メモに埋まる | 通常／即時の相談、報告先、判断期限、判断結果を独立して保存。即時報告は Commander へ |
| 担当の変更・引継ぎができない | 編成済みの実行担当へ手動引継ぎ。期限・成果物・確認記録・依存関係を保持し、指示者・報告先・伝え方を更新 |
| 編集で以前の指示が消える | 理由・記録者・日時・変更前後を追記。完了済み担当の変更と先行成果物未完了の着手を禁止 |
| 初稿の不足情報は作り直す必要がある | 同じミッションで目的・期限・KPI・確認日時を確定。未完了指示への反映はチェックして明示操作 |
| 再開時に新規作成が目立つ | 実行中ミッションへの継続ボタンを HOME 上部へ。通常ナビの先頭を司令室へ |
| スマホで次の行動が埋まる | 完了・判断待ち・保留・期限超過を冒頭へ。スマホは次の初動を KPI 詳細より先に表示 |

## 保存・権限

既存 `schemaVersion:2`、保存キー、履歴・能力設定を変更しない。Mission に任意の `execution`（version 1）を追加。既存 JSON はそのまま読め、新規記録は検証後に保存・バックアップ・追加復元する。無効・破損データは上書きしない。

判断結果の記録で保留を自動解除しない。担当が再開条件・期限を確認して指示を更新する。完了済み指示は条件一括変更から除外。実績がある KPI の定義・単位変更を禁止し、別ミッションへ分ける。

記録上の氏名は認証ではない。アプリは連絡・通知を送信しない。緊急時は直接連絡と現場手順を優先する。データは端末内のみで、共有・クラウド同期・実生成AIは未接続。
